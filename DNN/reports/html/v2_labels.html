A map fix, not a model fix

Swapping FKB Grønnstruktur's FKB_bygg for FKB Bygning 2018 corrects 11.9 km² of building footprint. It moves the deployed classifier by −0.0002 macro-F1 — and trying to learn from the correction makes the built class worse. Here is why that is the right outcome.

Verdict

Adopt v2 for the map. Keep the model as it is. Do not augment training with the changed pixels.

Retraining cannot move, so ask the inverse question: on the pixels v2 newly calls built, what did the deployed model already predict? 76,291 pixels, real lidar, 100% AlphaEarth coverage.

That is a resolution limit, not a model error — which is exactly why training on them hurts. Labelling grass-dominated mixed pixels "built" teaches the net to call grass built, and it pays for that on the 10 built pixels it used to get right.

06 What would actually move it

  • Adopt v2 for the map. 10.3 km² of correctly attributed rural building is a real cartographic improvement, independent of whether a 10 m classifier can learn from it.
  • Leave the training set alone. Both the relabel and the augmentation are non-wins; the augmentation is an active regression on built.
  • Isolated rural buildings need a different input, not more labels — FKB footprints as an explicit feature, or sub-10 m imagery. No amount of class-10 rows fixes a pixel that is 85% grass.
  • Class 13 remains an untouched blind spot. 691.6 km² of "other" is excluded from both training and evaluation — 58× the area this whole edit touches — and the model already reads 44% of it as built. That is unscored map surface, and a larger question than this edit.

Banked gotcha — embedding scale

aef_2024.vrt is float32 and already unit-normalised (measured L2/px = 1.0001, identical to the training parquet). The --scale 1000 convention applies to the int-scaled source.coop / GEE-export tiles, not here — applying it drives every feature to ~0 and silently yields confident nonsense rather than an error.

extract_v2_changes.check_embedding_scale() now raises if the median L2 strays from 1.0. Call it whenever a new embedding source is wired in.
