Scheme B all-years — best model

CC-APS conformal pseudo-labelling → TabICL stage-2 on the stable all-years AlphaEarth feature space, plus 3 lidar terrain features (elevation, ruggedness, canopy height). Macro-F1 0.7139 under spatially-blocked 3-fold CV — the most accurate model on the nyvest land-cover task to date. Adding the lidar features lifted the previous AlphaEarth-only best (0.7074) by +0.0065, with the gains concentrated in the natural-vegetation classes.

Approach

The model is a two-stage transductive pipeline that turns a large, partly-unreliable static land-cover map (grunnkart) and a temporal stack of AlphaEarth embeddings into a high-quality training set for an in-context tabular foundation model.

1. Data: stable all-years support

Grunnkart polygons are static, but AlphaEarth embeddings span 2017–2025. The stable set keeps pixel-years whose label is temporally consistent (663,740 rows). Classes 1 and 9 are merged into 2 (bare) and 8 (water/marine) respectively, leaving 10 classes. Using all years instead of 2020-only roughly 9× the support pool while keeping per-location label agreement.

2. Stage-1: CC-APS conformal pseudo-labelling of the unstable pool

  • A CatBoost stage-1 classifier is calibrated with cross-conformal APS (Adaptive Prediction Sets) at α=0.05, fully inside each CV fold (no test leakage).
  • The per-fold conformal threshold τ ≈ 0.937 yields prediction sets on the ~16.8k unstable rows. A row is accepted as a pseudo-label only when its prediction set is a confident singleton (the "standard" gate).
  • This keeps ~47% of unstable rows (n_kept ≈ 5.3k/fold) at a measured pseudo-label accuracy of ~85%, adding hard, spatially-novel examples that the stable set under-represents.

3. Support construction: dedup + cleaning + biased subsample

  • Location dedup: the stable support is reduced to one row per unique (lon, lat), keeping the most recent year, so TabICL sees ~79k spatially-diverse locations rather than 9× pseudo-replicates of the same pixels.
  • Class-12 cleaning (perfold_all_fix, train-only): snow/ice labels are stale due to fast 2017–2025 glacier retreat; melted class-12 pixels are spectrally infrastructure-like (class 11). Suspect rows (nearer to another class centroid than to the class-12 centroid) are corrected per location, train-side only — the test fold keeps original labels so F1 stays leak-free.
  • Biased subsample to TOTAL_SUP=32,000 support rows, force-including ~4,000 class-5 (grassland) rows, which is otherwise starved in a uniform draw.

4. Stage-2: TabICL in-context prediction

The deduped, cleaned, biased support (32k rows) is fed to TabICL (n_estimators=16, KV-cache enabled) as in-context examples; the full stable test fold is predicted in 1k-row chunks to bound GPU memory. TabICL's attention is O(n²) in support size, which is why 32k is the practical ceiling on a 24 GB A40.

Lidar terrain features (the +0.0065)

The current best adds 3 features from a 3 m local lidar product (data/lidar_features.parquet, extracted by scripts/extraction/extract_lidar_features.py) to the 64 AlphaEarth bands, joined by exact (lon, lat). The 3 were selected by a fast CatBoost CV probe (scripts/feature_probe_lidar.py) that mirrors this pipeline's CV contract, then confirmed on the full TabICL pipeline.

Probe findings that shaped the choice: elevation, terrain-ruggedness (tri) and canopy-height (tch) are the three most important features overall — each ranks above the best single AlphaEarth band by CatBoost LossFunctionChange. The lidar aspect (sin/cos) features had ≈0 importance and slightly hurt; slope was marginal — so all three were dropped, and the lean 3-feature set beat the full 6-feature lidar set in the probe (0.7043 vs 0.7021). The 30 m Copernicus GLO30 DEM stays a no-op and adds nothing on top of lidar — the 3 m elevation subsumes it. No AlphaEarth-band subset beat the full 64, so all 64 are kept.

The lidar gain is a vegetation-separability fix, not a class-12 fix. Unlike the earlier DEM attempt (which chased the snow/ice ↔ infrastructure split), the lidar gains land on the natural-vegetation classes that actually drag macro-F1: wetland (7) +0.016, settlement (10) +0.014, forest (4) +0.011, grassland (5) +0.008. Snow/ice (12) is flat (−0.004, within noise). Canopy height and fine terrain shape carry the structural signal the annual embedding lacks.

What moved the needle — and what didn't

  • Support size is the live lever. 25k → 0.7036, 32k → 0.7074, 36k → 0.7076 (saturated). All 3 folds gained ~+0.004 at 32k — consistent, not RNG. Gains concentrate in rare/confusable classes (cls12 +0.018, bare +0.009).
  • All-years support beats 2020-only (more spatially-diverse deduped locations), and train-only class-12 cleaning (perfold_all_fix) adds the final ~+0.007 over the no-force baseline (0.6964 → 0.7036 → 0.7074 with the larger support).
  • Conformal-gate noise correction for class 12 (nc-gate) is a no-op — ties the standard gate at 0.7036. The gate almost never pseudo-labels class 12 (~9 rows across all folds), so the correction has nothing to act on. Don't iterate further there.
  • Adding class-12 support rows (dedup-exempt) makes it worse (0.665 → 0.320): class 12 is spectrally near-inseparable from the 62×-larger class 11, so more cls12 context amplifies the 11↔12 contradiction. Keep dedup-exempt empty until a real 11-vs-12 discriminator exists.
  • Lidar terrain features are the current best lever (+0.0065). Three 3 m-lidar features — elevation, ruggedness (tri), canopy height (tch) — added on top of the AlphaEarth bands lift macro-F1 0.7074 → 0.7139, with gains on the vegetation classes (wetland +0.016, settlement +0.014, forest +0.011). They are the three most important features overall. Lidar aspect/slope were dropped (≈0 / marginal importance).
  • The 30 m Copernicus DEM (elevation/slope) added almost nothing over AlphaEarth and nothing on top of lidar — the 3 m lidar elevation subsumes it. The earlier "DEM won't fix 11-vs-12" finding still holds; the real win came from canopy/terrain structure helping the natural-vegetation confusions, not the snow/ice split.

Reproduce

# A40 GPU, support=32k + lidar features. Wrap in a memory scope: TabICL can spike host RSS to ~23 GB.
systemd-run --user --scope -p MemoryMax=40G -p MemorySwapMax=0 \
  env CLEAN_MODE=perfold_fix TOTAL_SUP=32000 EXTRA_FEATURES=lidar \
      OUT_SUFFIX=_perfold_fix_sup32k_lidar \
  ~/myprojects/recover/.venv/bin/python \
  common_ground/scripts/llto_schemeB_allyears.py
# 40k OOMs on the 24 GB A40 (all folds). The script fails fast if device != cuda with TOTAL_SUP > 8k.
# Drop EXTRA_FEATURES=lidar to reproduce the 0.7074 AlphaEarth-only baseline.
